# Quark 2.0.0 — mode Deck, parité 1.8.8 et sortie

Date : 21 novembre 2026
Branche : `release/2.0.0`, créée depuis `tauri-ui`
Statut : proposé au mainteneur

## Intention

Faire de la 2.0.0 la version qui officialise l'interface Tauri 2, avec un
différenciateur visible — un **mode Deck / manette** intégré — puis remettre à
niveau les fonctions de la 1.8.8 encore absentes ou partielles avant la sortie.

Ordre voulu par le mainteneur : **B (mode Deck), puis A (parité et sortie)**.
`main` n'est ni modifiée, ni fusionnée, ni poussée.

## Pourquoi

- Le portage Tauri justifie à lui seul un changement de version majeure.
- Le mode Deck transforme Quark en launcher utilisable sur Steam Deck et en
  salon, sans second binaire ni seconde interface.
- La 1.8.8 avait des fonctions qui manquent aujourd'hui : les laisser partir
  en 2.0.0 serait une régression perçue comme un recul malgré la nouvelle UI.
- La fenêtre doit rester opaque : la transparence nécessaire aux coins
  extérieurs arrondis réintroduit les pixels figés de WebKitGTK/Wayland.

## Objectifs

1. Mode Deck intégré : détection automatique, activation manuelle, navigation
   complète à la manette, fallback clavier, aucune régression hors mode Deck.
2. Parité 1.8.8 : téléchargements de boutique, scan/ajout, recherche globale,
   sources d'illustrations, accueil/bibliothèque, CLI.
3. Sortie 2.0.0 : version, notes, README, site, wiki, captures, dépendances de
   compilation et vérifications.

## Non-objectifs

- Pas de seconde application « Big Picture ».
- Pas de configuration de Steam Input, pas de support Windows/macOS/Android.
- Pas de synchronisation distante de bibliothèque, pas d'API de plugins.
- Pas de Steam Cloud, pas de nouvelle API graphique pour l'overlay.
- Pas de retour aux coins extérieurs arrondis.
- Pas de fusion ni de push sur `main`.

## Contraintes

- Linux, Tauri 2, WebKitGTK 4.1, cœur Rust sans egui.
- Cinq langues et treize thèmes conservés ; tout nouveau libellé passe par
  l'i18n et les cinq catalogues.
- Une seule nouvelle dépendance native : `gilrs` (entrées manette Linux).
- Performances : pas de rendu complet par événement de manette, pas de
  dépendance à un GPU, budget mémoire inchangé hors mode Deck.
- Le mode Deck ne doit pas intercepter les entrées quand un jeu a le focus.

## Approches

### B — entrées manette

1. **Gamepad API dans WebKitGTK.** Zéro dépendance, mais support et mappings
   variables, hotplug moins fiable, comportement différent du reste du bureau.
2. **`gilrs` côté Rust + événements Tauri + navigation spatiale** — retenu.
   Entrées Linux fiables, hotplug, deadzone et répétition contrôlées, un seul
   chemin pour Steam Deck et bureau.
3. **Steam Input en mode clavier + skin console.** Aucun code d'entrée, mais
   dépend de Steam et ne fonctionne pas hors Deck. Conservé comme fallback
   documenté, pas comme implémentation principale.

### A — parité

1. **Réparer dans l'interface et les commandes existantes** — retenu. Le cœur
   Rust et les composants UI sont bons ; il manque des branchements.
2. **Réécrire les écrans concernés.** Rejeté : risque élevé, aucun gain visuel.
3. **Reporter la parité en 2.1.** Rejeté : la 2.0.0 doit être une montée de
   version sans régression fonctionnelle.

## Design B — mode Deck

### Détection et activation

- Nouveau réglage `deck_mode` : `auto` (défaut), `on`, `off`.
- `auto` active le mode si l'un de ces signaux est vrai :
  - `SteamDeck=1` dans l'environnement ;
  - `/sys/class/dmi/id/product_name` vaut `Jupiter` ou `Galileo` ;
  - session `gamescope` (`XDG_CURRENT_DESKTOP` ou `GAMESCOPE_WAYLAND_DISPLAY`) ;
  - une manette est connectée **et** le réglage utilisateur l'autorise.
- L'état est exposé par une commande `deck_status` et un événement
  `quark://gamepad-status`.
- Bascule manuelle : icône manette dans la barre supérieure et entrée dans
  Réglages → Apparence. Sortie par le menu Start, pas par un appui accidentel.

### Entrées

- Module `quark-tauri/src/gamepad.rs`, thread dédié `gilrs`.
- Mapping par défaut :
  - Sud/A : valider ; Est/B : retour ; Ouest/X : jouer ; Nord/Y : favori ;
  - croix et stick gauche : navigation ; gâchettes : onglets précédent/suivant ;
  - Start : menu du mode Deck ; Select : basculer les aides.
- Répétition des directions après 350 ms, toutes les 110 ms ; deadzone 0,45.
- Événements `quark://gamepad` : `{ action, pressed }`, uniquement sur
  changement ou répétition. Aucune image gaspillée.
- Entrées ignorées si `document.hasFocus()` est faux ou si un jeu est au premier
  plan ; reprise automatique au retour.
- Fallback clavier : flèches, Entrée, Échap, `Début` pour le menu.

### Interface

- `deck.js` : état, navigation spatiale, focus, aides, activation.
- `deck.css` ou section dédiée de `styles.css` : `body.deck`.
- Écrans adaptés, pas dupliqués :
  - barre supérieure large, sans contrôles de fenêtre redondants ;
  - accueil plein écran avec héros et rayons ;
  - bibliothèque en grandes tuiles, fiche plein écran ;
  - boutique et mes jeux en grille large ;
  - réglages en colonne lisible, contrôles agrandis ;
  - modales centrées et focalisables.
- Anneau de focus unique, contraste élevé, `scrollIntoView({ block: "nearest" })`.
- Pied de page : `A Ouvrir · B Retour · X Jouer · Y Favori · LB/RB Onglets ·
  Start Menu`.
- Recherche : champs focalisés ; clavier virtuel Steam accepté. Un clavier
  interne pourra venir après la 2.0.0.

### Plein écran et persistance

- Commande `win_set_fullscreen(bool)` ; le mode Deck mémorise l'état précédent.
- `deck_mode` et l'état du mode sont sauvegardés dans `config.json` avec les
  autres réglages, jamais dans un fichier séparé.
- Aucun changement de thème forcé : le thème courant reste appliqué.

### Tests et vérification

- Tests unitaires Rust : détection, mapping boutons, deadzone, répétition.
- Mode démo `--deck` pour rendre les écrans Deck sous Xvfb.
- Captures : accueil, bibliothèque, fiche, réglages, modale, aides.
- Vérification manuelle sur Steam Deck ou session gamescope si disponible.
- Vérifier que le mode normal, le scroll et les médias ne changent pas.

## Design A — parité et sortie

### A1. Téléchargements de boutique

- Enregistrer les tâches d'installation dans `AppState` (clé
  `provider:productId`, jeton d'annulation, progression partagée).
- `provider_install` démarre la tâche, émet
  `quark://provider-install-progress` (pourcentage, étape, vitesse, ETA,
  octets) et rend la main sans bloquer l'interface.
- `provider_cancel` annule proprement le processus enfant.
- Maximum trois téléchargements simultanés.
- UI : icône de téléchargement dans la barre, panneau des transferts, annuler,
  état dans Mes jeux, rafraîchissement à la fin.
- Aucun événement de progression si la boutique n'en publie pas : afficher
  l'étape et une barre indéterminée.

### A2. Ajout, scan, sites et illustrations

- Commandes `scan_folder`, `site_search`, `artwork_candidates`,
  `artwork_choose`.
- Dialogue d'ajout en trois onglets : manuel, scanner un dossier, rechercher.
- Le scan réutilise `quark::scan`, propose les exécutables et ajoute la
  sélection en lot.
- La recherche de sites ouvre uniquement des pages dans le navigateur ; aucun
  téléchargement.
- Illustrations : galerie de candidats SteamGridDB/Steam, choix par type,
  conservation du fichier local existant.

### A3. Recherche globale et raccourcis

- Étendre la palette `Ctrl+K` aux réglages, aux jeux de boutique et aux
  actions ; ajouter `Ctrl+F`.
- Conserver la recherche sans accents et le lancement par Entrée.
- Ajouter `Ctrl+Q` pour quitter réellement.
- Afficher l'exécutable manquant en rouge dans la liste, pas seulement dans la
  fiche.

### A4. Accueil et bibliothèque

- Ajouter la bibliothèque complète sous les rayons de l'accueil.
- Bouton du héros : `Jouer`, `Continuer` ou `Arrêter` selon l'état réel.
- Conserver la disposition Steam liste à gauche / fiche à droite en mode
  normal ; le mode Deck est une variante plein écran.

### A5. CLI

- Restaurer `--doctor`, `--search`, `--fetch`, `--news`, `--scan`, `--update`.
- `--doctor` imprime configuration, données, artworks, préfixes, racine Steam,
  runtimes Proton, jeux et état de résolution.
- `--search`/`--fetch` s'appuient sur `artwork` ; `--news` sur `news` ;
  `--scan` sur `scan` ; `--update` sur `update`.
- `--ui` et `--tray` restent absents : remplacés par Xvfb et le tray Tauri.

### A6. Sortie 2.0.0

- Version `2.0.0` dans `Cargo.toml`, `quark-tauri/Cargo.toml` et
  `quark-tauri/tauri.conf.json`.
- `docs/release-notes.md` réécrit pour 2.0.0 ; README remis à jour pour Tauri,
  Deck, dépendances et CLI.
- Site, wiki et captures `docs/images` + `site/assets` mis à jour.
- Workflow release : ajouter `libudev-dev`; vérifier le paquet et le SHA-256.
- Vérifications : `cargo fmt --all --check`, clippy `-D warnings` sur les deux
  crates, tests root, tests Tauri, captures Xvfb mode normal et Deck.

## Ce qui reste au constructeur

- Choisir la forme exacte du panneau de transferts (tiroir ou fenêtre).
- Décider si le clavier interne Deck arrive en 2.0 ou 2.1.
- Ajuster les tailles Deck après captures réelles.
- Porter les commandes CLI une par une en réutilisant le code de `main` comme
  référence, sans réintroduire egui.
- Ne jamais toucher `main` ni publier la branche sans demande explicite.

## Critères d'acceptation

- Mode Deck activable automatiquement et manuellement, navigable entièrement à
  la manette et au clavier, sans régression hors mode.
- Aucune régression de scroll, de transparence ou de lecture média.
- Toutes les fonctions de la matrice de parité ci-dessous sont présentes, ou
  explicitement déclarées hors périmètre.
- Version 2.0.0, notes, README, site, wiki et captures cohérents.
- `cargo fmt`, clippy et tests verts.
